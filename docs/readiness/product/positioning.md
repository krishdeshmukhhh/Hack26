# Positioning and presentation wording

24 October 2026. Recommendations are product inferences informed by the
[research audit](problem-and-audience.md), [alternatives](comparison.md) and
[claim audit](claim-audit.md), not validated market findings.

## Audience and promise

Initial audience hypothesis: students and self-directed adults attempting an
unfamiliar task in feature-rich Windows software. Start with one application and
a task whose final result can be checked. Avoid “people who cannot use computers”
and do not infer an accessibility audience from an animated pointer.

**One sentence:** Curio is a Windows voice companion that explains the
current screen and points through unfamiliar software tasks, with recorded paths
and inspectable estimates to inform later help.

**Strongest angle:** show how assistance can change on the next encounter. The
contribution is integrating screen-grounded steps, reusable task records and
visible assistance estimates. Screen awareness already has alternatives. This is
a demonstrable system claim without a new-category or improved-learning claim.

## Proposed demonstration, not a completed experiment

1. Ask for help with a prepared unfamiliar task. Show the target and next
   screen-aware step after the user acts. A human checks the final application state.
2. Open the recorded path/Skills evidence. Explain the success signal was inferred
   from model output and the estimate is heuristic and resettable.
3. Repeat the task request and show changed assistance context. Seeded history must
   say **SIMULATED HISTORY** on screen and use an isolated database. Report any
   live model failure to honor the hint-only request.
4. Show Escape/cancel and one recovery case. Keep the polynomial tutor optional:
   it illustrates a bounded independent checker, not ordinary GUI verification.

An illustrative “before” sequence can show tutorial → application → missing
control → return/rewatch. Label it illustrative with no invented time/click savings.
Label fallback recordings recorded. Scripted replies and the two-instance test
are component exhibits, not two actual users/laptops.

## Questions to answer candidly

| Question | Defensible response |
| --- | --- |
| Why not Copilot Vision? | It already offers screen-aware discussion/highlighting. We explore linking step records and inspectable concept estimates to later help. Superiority is unmeasured. |
| Why not an interactive tutorial? | Authored tutorials support repeatable processes. Curio requests help from the current screenshot and reuses recorded paths; reliable recovery remains unmeasured. |
| Does it learn what I know? | It computes an estimate from interaction records using assumed parameters. You can inspect/reset it; it is not a calibrated knowledge test. |
| How do you know a task is done? | Ordinary progression relies on model output. An observer must check the result. The separate exact tutor checks only supported polynomial work. |
| What is the pet for? | Customizable desktop presence/pointer. No evidence it improves learning or reduces anxiety. |
| Is it all local? | Storage and some speech can be local. Screenshots/document text go to configured inference; optional map sharing sends textual summaries. |
| How much does it help? | Implementation/test evidence and relevant external research exist. Curio user outcomes remain unmeasured. |

## Future aspirations

Reliable wrong-state recovery, calibrated help fading, demonstrated transfer,
accessible interaction for additional populations and shared knowledge across
real users need new evidence. Describe them as questions the prototype enables
us to investigate. Do not claim first/unique, speed gains, retention, adoption,
scam prevention or willingness to pay.
